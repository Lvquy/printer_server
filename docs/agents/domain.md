# Domain docs

## Before exploring

Read root CONTEXT.md and the ADRs in docs/adr/ relevant to the task.
If a document is absent, proceed without requiring scaffolding.
Use /domain-modeling when new terms or decisions need recording.

## Layout

Single-context:
- CONTEXT.md — domain glossary.
- docs/adr/ — architecture decisions.

## Vocabulary

Use the glossary's terms in issues, explanations, code and tests.
For a missing concept, check existing terminology before proposing a term.

## Decision conflicts

Explicitly identify any proposal that contradicts an ADR.
Explain why the decision should be reopened instead of silently replacing it.
